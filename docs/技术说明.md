# CultureCheck 技术说明（v1）

## 1. 流程

```
上传（≤1280px JPEG）→ 视觉侦察员 → [文化顾问, 合规守卫] × 每个市场（并行）
  → 去重 → 决策官（每个市场一次调用：逐条仲裁 + 上架决策）→ 打分 → 报告
  → （可选）修图艺术家逐元素框选编辑 → 对修正版完整复检
```

| 智能体 | 默认模型 | 接口 |
|---|---|---|
| 视觉侦察员 | `qwen3-vl-plus` | DashScope OpenAI 兼容 `/compatible-mode/v1/chat/completions`，`response_format: json_object` |
| 文化顾问 / 合规守卫 | `qwen3.7-plus`（`enable_thinking:false`） | 同上 |
| 决策官 | `qwen3.7-plus`（`temperature: 0`） | 同上 |
| 修图艺术家 | `wan2.7-image` | `/api/v1/services/aigc/multimodal-generation/generation`，`parameters.bbox_list` |

千帆可替换视觉、复核与决策（`qianfan.baidubce.com/v2`，OpenAI 兼容）。

## 2. 坐标

视觉模型输出 `bbox_2d = [x1, y1, x2, y2]`，0–1000 归一化。前端直接换算为百分比绝对定位；修图时乘以当前图片像素尺寸。实测茶具图：横幅 `[10,16,990,203]`、白菊 `[0,215,292,447]`、OK 手势 `[749,623,999,999]`，与目视位置一致。

## 3. 规则库

`src/lib/rules.ts`，6 个市场 18 条（站内可浏览：`rules.html`），每条含：`id / market / kind(culture|compliance) / category / level / reason / suggestion / sources[]`，来源链接均已逐条打开核对。复核模型的 system prompt 只给出本市场、本类别允许的规则，输出里引用了不存在的规则 ID 的条目会被丢弃。

| 市场 | 规则 |
|---|---|
| 日本 | 数字 4 / 9、白菊、OK 手势（钱）、日文标签 |
| 巴西 | OK 手势、葡语标签 |
| 沙特 | 猪肉与酒精禁运、清真认证、OK 手势、左手、阿语标签 |
| 美国 | Made in USA 声明（FTC）、原产国标注（CBP） |
| 德国 | §86a 违宪标志、OK 手势 |
| 印度 | 牛肉、法定计量标签（进口商 / MRP） |

## 4. 决策官

文化顾问与合规守卫给出候选结论后，决策官对每个市场做一次仲裁（`qwen3.7-plus`，JSON 输出，温度 0）。输入为该市场全部结论（图中元素、命中规则及其基准等级与来源、复核理由与置信度、2–3 个替换方案）以及商品类目、渠道与文案，输出：

- `keep`：结论成立且需要处理的概率（要求校准），< 0.3 剔除，< 0.6 标「建议人工确认」
- `level`：high / mid / low，且只能在规则基准等级 ±1 级内调整
- `option`：从替换方案中选出消除风险且改动成本最低的一个
- `launch`：该市场的上架决策 go / fix_then_go / no_go 及置信度

## 5. 打分

`100 − Σ(高 20 / 中 10 / 提示 2)`，置信度 < 0.6 的结论标「建议人工确认」不扣分。≥ 90 可上架，60–89 建议修改，< 60 需整改。

## 6. 修图边界

- 同一规则、框相交或相邻的元素合并为一个框；每次调用只编辑一个框（实测比一次两框更稳），最多 5 处。
- 不进入修图：商品本身属性（`in-beef`）、需要真实认证或标签的条目（清真、各国语言标签、原产国、印度 MRP）、卖点文案。提示词明确禁止添加任何认证标志或声明。
- 修正版会重新跑完整体检。复检结果来自模型对新图的独立识别，元素拆分可能与原图不同，因此前后得分是“重新体检”的结果，不是简单相减。

## 7. 追问体检团（对话）

- 入口：结果页右侧「追问体检团」。上下文为压缩后的报告 JSON（元素、各市场得分、结论、规则名与来源），最近 8 轮对话随请求发送。
- 系统提示要求：只依据报告回答；报告没覆盖的明确说明；引用结论时写出市场与风险等级；中文、220 字以内。
- 演示报告：4 个示例提示词的回答由 qwen3.7-plus 基于同一份报告真实生成，存于 `public/i18n/demo-*-chat.json`；自由提问会提示配置 Key。

## 8. 多语言报告

- 导出语言：中文 / English / 日本語，适用于 PDF、圈注长图 PNG 与 Markdown + JSON。
- 翻译范围：产品名、元素名、每条结论的标题 / 位置 / 原因 / 建议、通过项；界面标签用内置词表。
- 真实报告由复核模型翻译一次后缓存到 IndexedDB；演示报告的翻译预先生成，存于 `public/i18n/demo-*.json`。

## 9. 跨域与部署

| 接口 | 浏览器直连 |
|---|---|
| DashScope 对话（`dashscope.aliyuncs.com` / `dashscope-intl.aliyuncs.com`） | ✅ `Access-Control-Allow-Origin: *` |
| 万相图像编辑 + 结果 OSS 链接 | ✅ |
| 千帆 v2（`qianfan.baidubce.com/v2`） | ✅ 预检返回 `Access-Control-Allow-Origin: *`；无效 Key 时返回 401 并在界面提示。完整流程尚未用真实千帆 Key 跑通 |

站点为纯静态文件，无后端、无代理；GitHub Actions（`.github/workflows/pages.yml`）构建后发布到 GitHub Pages。

## 10. 隐私

- Key 只在 localStorage；仓库与构建产物不含任何 Key。
- 图片只在浏览器与模型接口之间传输；结果存 IndexedDB，可在设置里一键清除 Key。
